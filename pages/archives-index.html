This template is written to work correctly either way, with no changes needed if that migration happens later: jekyll-paginate-v2's paginator object uses identical field names to v1 (paginator.posts, .page, .total_pages, .previous_page(_path), .next_page(_path), confirmed from its docs, including the loop variable staying `posts` in collection mode) - paginator only exists on a page where a real pagination generator actually ran, so testing for its presence is enough to branch between "real, plugin-driven pagination" and "no plugin, list everything." To activate real pagination later, add `pagination: { enabled: true, collection: archives, sort_field: weight, sort_reverse: false }` to this file's front matter and install jekyll-paginate-v2 - nothing below needs to change.
