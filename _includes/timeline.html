Events render in the order they appear in _data/timelines.yml - this template deliberately does not sort them, so the data file stays the single source of the running order. `date` may be a real date or free text, and the two are told apart by .size: a string answers it, a Date object doesn't. Only real dates are passed through the `date` filter, because that filter quietly mangles partial dates - "2003" is read as a Unix timestamp and renders as 31 Dec 1969, and "June 2003" becomes 1 Jun 2003, inventing a day that was never written.
